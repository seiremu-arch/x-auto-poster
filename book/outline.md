# 書籍 構成案

『**はじめてのAI開発 ― Cursor・Claude Code・GitHubと歩く、物語のはじまり**』(仮題)

---

## 1. コンセプト

- **ジャンル**: 解説書ベース + 短編物語(ビジネス小説的な導入エピソード)
- **狙い**: プログラミング未経験〜初心者が、Cursor / Claude Code / GitHub という3つの道具を「なぜ・どう使うか」を、実在の開発現場を模した物語の中で追体験しながら理解する。
- **構成方針**:
  - 各章は**技術解説がメイン**(操作手順・概念・つまずきポイント・実例コード)。
  - 各章の冒頭または要所に**2〜4ページ程度の短い物語エピソード**を挿入し、「なぜこの技術が必要になったか」を主人公の視点で描く。
  - 物語パートは寓話的に誇張しすぎず、実際の開発者が体験する失敗・気づき・達成感をリアルに描写する。

## 2. 想定読者

- プログラミング未経験〜初心者(ITエンジニア以外の職種、学生、副業・個人開発に興味がある人)
- 「AIに頼めばコードは書けるらしいが、実際何をどう学べばいいのかわからない」層
- 前提知識: PCの基本操作ができれば十分。専門用語は初出時に必ず解説する。

## 3. 主人公・世界観(物語パート)

- **主人公**: 田中 光(たなか ひかり)・28歳。小さなカフェを一人で経営している非エンジニア。
- **動機**: 常連客からの「予約を紙とLINEでやっていて限界」という声をきっかけに、自分のお店専用の予約管理アプリを作ろうと思い立つ。
- **相棒**: 元エンジニアで今はカフェの常連客でもある「先生」役の登場人物(メンター)。光がAIツールの使い方に迷うたびに、要点だけをヒントとして与える。
- **トーン**: 等身大の試行錯誤(エラーに戸惑う、思った通りに動かない、けれど一つずつ理解して前進する)を描き、技術解説と地続きにする。

## 4. 全体構成(章立て)

| 章 | 章タイトル(仮) | 学ぶ技術内容 | 物語エピソード概要 |
|---|---|---|---|
| 序章 | 光、決意する | 本書の読み方・AI開発とは何か・全体地図 | 紙の予約ノートが限界を迎える夜。光が「自分でアプリを作る」と決める |
| 第1章 | 机の上に、道具をそろえる | Cursorのインストールと基本画面/エディタの概念/ファイルとフォルダ | 先生から「まずは道具を用意しよう」とCursorを勧められる |
| 第2章 | AIに、話しかけてみる | Cursorでのチャット・プロンプトの書き方の基本/良い指示・悪い指示 | 初めてAIにお願いした指示が的外れで空回りする体験 |
| 第3章 | 手を動かすAI、Claude Codeとの出会い | Claude Codeとは何か/ターミナルの基礎/CLIでの対話型開発 | 先生に勧められてClaude Codeを導入。画面ではなく会話でコードが動く驚き |
| 第4章 | 小さく作って、確かめる | ファイル生成・簡単な機能追加の依頼の仕方/動作確認の習慣 | 予約フォームの試作第一号ができる。想定と違う挙動に戸惑う |
| 第5章 | 失敗を、なかったことにしない | エラーメッセージの読み方/AIへのデバッグ依頼の仕方 | 保存したはずのデータが消える不具合。原因を一緒に追う |
| 第6章 | 変更を、記録に残す | Gitの基本概念(コミット・履歴)/なぜバージョン管理が要るか | 「昨日動いていたのに今日は動かない」を経験し、Gitの必要性を痛感 |
| 第7章 | 世界とつながる、GitHub | GitHubアカウント/リポジトリ/push・pullの基本 | 先生に「クラウドに置いておけば安心」と勧められ、初めてpushする |
| 第8章 | 枝分かれして、また合流する | ブランチ運用/プルリクエストの考え方 | 新機能(通知メール)を試すために枝分かれ。うまくいかず本流に戻す判断 |
| 第9章 | もう一人の目、コードレビュー | AIによるコードレビュー/Issueの立て方/変更提案の読み方 | 先生からの指摘とAIレビューの両方を受け、直す優先順位に悩む |
| 第10章 | 育てながら、公開する | 継続的な機能追加/簡単なデプロイ/リリースの区切り方 | 予約アプリを常連客に初めて使ってもらう日 |
| 第11章 | 一人からチームへ | 共同編集・コンフリクト・GitHubでの共同作業の基礎 | 別のカフェオーナーが「うちにも欲しい」と加わり、共同開発が始まる |
| 終章 | 光の、これから | 学びの振り返り/次に学ぶべきこと/AI時代の開発との付き合い方 | 半年後の光の店。アプリは育ち続けている |
| 付録 | 実践チートシート | 頻出プロンプト集/用語集/トラブルシューティング表/参考リンク | ― |

## 5. 各章の分量イメージ

- 技術解説パート: 1章あたり本文 3,000〜5,000字
- 物語エピソード: 1章あたり 800〜1,500字
- 全14パート(序章+11章+終章+付録)で、総文字数はおおよそ 60,000〜80,000字 を想定

## 6. 次のステップ

1. 本outlineのタイトル・主人公設定・章立ての方向性をご確認いただく
2. 確定後、サンプルとして **序章+第1章** を実際の文体で執筆し、トーンを確認
3. 問題なければ残りの章を順次執筆
