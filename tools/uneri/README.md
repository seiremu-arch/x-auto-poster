# うねり取り バックテスト (`tools/uneri/`)

ETF1銘柄を長く追い、平均回帰する波に対して**買い下がり・売り上がり**を分割で行う
（うねり取り）ためのバックテストと日次シグナル。

このリポジトリ本体（RSS収集 / サイト生成 / Vault）とは独立している。依存は
標準ライブラリのみで、`scripts/` には触らない。

```bash
python tools/uneri/uneri.py synth    --out /tmp/synth.csv --years 12   # 検証用の合成日足
python tools/uneri/uneri.py fetch    --ticker 1306.T --out data/1306.csv
python tools/uneri/uneri.py backtest --csv data/1306.csv --lot 10
python tools/uneri/uneri.py sweep    --csv data/1306.csv --lot 10
python tools/uneri/uneri.py signal   --csv data/1306.csv --units 2 --avg-cost 2810
python -m unittest discover -s tools/uneri/tests           # 37件
```

## ルール（既定値）

相場が動いている最中に決めないために、ここに固定してある。変えるなら相場が
閉じているときに、CLIオプションではなくこのファイルを書き換える。

**ものさし**は終値だけ。ザラ場は見ない。

```
乖離率 = (終値 - 25日移動平均) / 25日移動平均 × 100
地合い = 終値が200日移動平均の上か下か
```

**買い下がり**（1段 = 20万円、上限5段 = 100万円）

| 段 | 発動条件 | 累計 |
|---|---|---|
| 1 | 乖離 −3% 以下 | 20万 |
| 2 | 乖離 −5% 以下 | 40万 |
| 3 | 乖離 −7% 以下 | 60万 |
| 4 | 乖離 −10% 以下 | 80万 |
| 5 | 乖離 −13% 以下 | 100万 |

段は上から順に1つずつ。**同じ日に2段は建てない**。前の建玉から最低3営業日空ける。
そして**5段目で打ち止め**。ナンピンと分割売買を分けるのはこの一行だけで、
破産するかしないかもここだけで決まる。

**売り上がり**

| 段階 | 条件 | 落とす量 |
|---|---|---|
| 1 | 平均建値 +3% | 建玉の 1/3 |
| 2 | 平均建値 +6% | 残りの 1/2 |
| 全 | 乖離 +4% 以上、または200日線を下から上抜け | 全部 |

**撤退**（`--no-stop` で無効化できる）

> 満玉かつ平均建値 −18% で、建玉の半分を落とす。1サイクルに1回だけ。

古典的なうねり取りは損切りをしない（上限を守っていれば時間が解決する、という
思想）。指数ETFならそれでも成立しうるが、戻るまで2年以上かかる下げは実際にある。
入れるか入れないかを先に決めて、決めたら動かさない。

## 何が分かったか（合成データ12年 × 2本）

実データは取れていない（後述）ので、以下は**合成データでの挙動**であって
将来の成績の予想ではない。それでも、この手法の性格ははっきり出る。

| 相場 | うねり取り(税引後) | バイ&ホールド(税引後) | 差 |
|---|---|---|---|
| 上昇（年率+5%ドリフト） | +18.4% | **+70.2%** | **−51.8万円** |
| 横ばい（ドリフト0%） | **+27.6%** | −14.4% | **+42.0万円** |

**うねり取りは横ばい相場の技術**で、上げ相場では構造的にバイ&ホールドに負ける。
負け方の中身は勝率ではない（上昇相場でも勝率は92%ある）。負ける理由は2つだけ。

1. **資金がほとんど遊ぶ。** 建玉していた日は全体の21%、平均建玉率はわずか4.2%。
   上限100万を用意して、実際に市場に置かれていたのは平均4万円。投下資本あたりの
   年率は48%だが、総資金ベースでは1.5%にしかならない。
2. **回すたびに課税される。** 上の例で23万円の利益に対し4.7万円を納税している。
   バイ&ホールドは売るまで課税されない。

この2つは戦略の良し悪しではなく**構造**なので、パラメータをいじっても消えない。

もう1つ、設計上の重要な性質が検証で出た。

> **段は「一発の急落」では埋まらない。「下げが続くとき」にしか埋まらない。**

25日線は下げを追いかけて数日〜数週間で追いつくので、一度落ちて横ばいになると
乖離はすぐ0に戻る。実際、合成データ12年で**満玉（5段）に到達した回数は0回**、
3段到達が2回だった。深い段は「使われない保険」であって、多くの場合、勝敗は
1段目と2段目で決まる。段を深く設計しすぎると資金が遊ぶだけになる。

## 使い方

### 1. データを用意する

`fetch` は Yahoo Finance の日足を取る。**この機能は開発環境のネットワーク
ポリシーで検証できていない**（`query1.finance.yahoo.com` への接続が遮断されている）。
手元で通らなければ手動で用意する:

- 証券会社の履歴CSV（Shift_JIS・日本語ヘッダ）をそのまま読める
- 必要な列は `日付 / 始値 / 高値 / 安値 / 終値`（英語ヘッダも可）
- `Adj Close` があれば既定でそちらを使う（分配金の権利落ちを均すため）。
  実際の売買価格で見たいときは `--raw-close`

動作確認だけなら `synth` で合成データを作れる。

### 2. 回す

```bash
python tools/uneri/uneri.py backtest --csv data/1306.csv --lot 10 \
    --out-trades data/tamacho.csv --out-equity data/equity.csv
```

`--lot` は売買単位（1306は10、1321は1）。既定の執行は**翌日始値**——終値を見て
判断し、翌朝に約定する、という実際の手順に合わせてある。`--exec-at close` に
すると当日終値で約定したことになり、成績は実態より良く出る。

建玉が残ったままデータが終わった場合は最終終値で強制決済して計上する。
含み益のまま終わらせると成績が実態より良く見えるため。

### 3. 感度を見る

```bash
python tools/uneri/uneri.py sweep --csv data/1306.csv --lot 10
```

1段目・段の間隔・利食い幅を総当たりする（既定64通り、1秒弱）。
**上位が「正しい」わけではない。過去に最も合った形はたいてい過剰適合。**
見るべきは、隣のパラメータに動かしたときに成績が崩れないかどうか。
崖の上に立っている組み合わせは、実運用では崖の下に落ちる。

### 4. 毎晩

```bash
python tools/uneri/uneri.py signal --csv data/1306.csv --units 2 --avg-cost 2810
```

今日の乖離、地合い、次に発動する段、利食いの判定を1画面で出す。
これを見て**玉帳に書く**。

## 玉帳

うねり取りの本体はルールではなく記録。`--out-trades` の出力と同じ形。

| 日付 | 売買 | 単価 | 口数 | 約定額 | 建玉合計 | 平均建値 | 25日乖離 | 200日線 | 評価損益 | 所感 |
|---|---|---|---|---|---|---|---|---|---|---|
| 2026-09-18 | 買1 | 2,840 | 70 | 198,800 | 70 | 2,840 | −3.2% | 上 | −1,200 | 決算跨ぎ前 |

「所感」欄が効く。半年分溜まると、自分がどこで焦って買い、どこで早く利確して
いるかが数字で見える。これ抜きでやると、ただの気分のスイングトレードになる。

## 設計上の約束

- **買い専**。指数ETFには長期の上昇ドリフトがあるので売り玉は構造的に不利。
  現物のみなら追証も逆日歩もなく、最悪でも「その指数を持っている人」で止まる。
- **原価は総平均法**。特定口座の計算と同じ。部分利食いをしても平均建値は動かない。
- **税は売却のたびに源泉**し、損失は繰り越して将来の利益と相殺する
  （特定口座・源泉徴収ありの挙動）。
- **手数料は既定0円**（ネット証券の現物ゼロコース前提）。`--fee` で変えられる。

## 検証していないこと

- **実際の市場データでの成績**。合成データは平均回帰を作り込んであるので、
  うねり取りに有利に出ている可能性がある。実データで回すまで結論は出ない。
- **`fetch` サブコマンド**。ネットワークが遮断された環境で書いたため未実行。
- **売買代金の影響**。板が薄い銘柄でのスリッページは考慮していない
  （1306クラスなら数百万円まで実質ゼロだが、それを前提にしている）。
- **分配金**。`Adj Close` を使えば総リターンに均されるが、実際の入金と
  課税のタイミングは再現していない。
