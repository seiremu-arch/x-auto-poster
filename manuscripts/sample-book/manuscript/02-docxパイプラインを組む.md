# 第2章　docxパイプラインを組む

Markdownの原稿をdocxに変換する部分が、パイプラインの中心になる。

## docxは要するにZIPである

`.docx`はXMLファイルを集めたZIPアーカイブにすぎない。拡張子を`.zip`に変えて展開すれば、中身を直接見られる。

```bash
unzip -o book.docx -d unpacked/
ls unpacked/word/
# document.xml  styles.xml  settings.xml  numbering.xml  ...
```

本文の中身は`word/document.xml`に入っている。段落は`<w:p>`、文字の並びは`<w:r>`（ラン）、実際の文字は`<w:t>`だ。つまりdocxの生成とは、**XMLを組み立ててZIPに詰める**という作業でしかない。

## 見出しはスタイルで指定する

ここで最も重要なのが、見出しの扱いだ。見出しを「太字の18ポイント」として直接指定してはいけない。かならずWordの組み込みスタイル`Heading 1`〜`Heading 3`を使う。

```xml
<w:p>
  <w:pPr><w:pStyle w:val="Heading1"/></w:pPr>
  <w:r><w:t>第2章　docxパイプラインを組む</w:t></w:r>
</w:p>
```

理由は2つある。ひとつは、Wordの目次フィールドがスタイルを見て目次を組み立てるから。もうひとつは、**KDPの変換エンジンがスタイルを見てKindleの目次を作るから**だ。見た目だけ整えた「太字の大きな文字」は、KDPからは本文の一部にしか見えない。

スタイル定義側には`outlineLvl`も入れておく。

```xml
<w:style w:type="paragraph" w:styleId="Heading1">
  <w:name w:val="heading 1"/>
  <w:pPr>
    <w:pageBreakBefore/>
    <w:outlineLvl w:val="0"/>
  </w:pPr>
</w:style>
```

`pageBreakBefore`をスタイルに入れておくと、章の先頭が必ず新しいページから始まる。原稿側に改ページを書き込む必要がなくなる。

## 章の区切りをどう決めるか

章の切れ目は、`#`見出しの位置で決まる。ファイルを分けておくと扱いがさらに簡単になる。

- `00-まえがき.md`
- `01-制作工程を分解する.md`
- `02-docxパイプラインを組む.md`

ファイル名の数字が章順になるので、章を入れ替えたいときはファイル名を変えるだけでいい。設定ファイルの`manuscript`にはglobを1行書いておけば足りる。

```yaml
manuscript:
  - manuscript/*.md
```

## ルビと画像

日本語の本ではルビが要ることがある。青空文庫と同じ記法で書けるようにしておくと、原稿が読みやすい。

｜組版《くみはん》はこう書くと、docxでは`w:ruby`要素に、EPUBでは`<ruby>`タグに変換される。漢字《かんじ》のように縦棒を省いても、直前の漢字列に自動でかかる。

図版は単独行の画像記法で入れる。角括弧の中身がそのままキャプションになる。

```markdown
![図1　原稿から入稿ファイルまでの流れ](../assets/pipeline.png)
```

パスは原稿ファイルからの相対、または本のディレクトリからの相対で書ける。画像はピクセル数と解像度を読み取って、版面の幅に収まるサイズで埋め込まれる。ペーパーバックのプロファイルでは、300dpiに足りない画像が入稿前チェックで警告される。
