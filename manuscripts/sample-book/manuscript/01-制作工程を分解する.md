# 第1章　制作工程を分解する

自動化の第一歩は、工程を細かく分けることだ。「本を作る」というひとかたまりの作業のままでは、どこを機械に任せられるのか見えない。

## 5つの工程

個人出版の制作工程は、おおよそ次の5つに分けられる。

1. 執筆 — 原稿そのものを書く
2. 構成 — 章の順番を決め、見出しの階層を整える
3. 組版 — 判型・余白・フォント・目次を確定させる
4. 検査 — 入稿要件を満たしているか確認する
5. 入稿 — KDPにファイルをアップロードする

このうち機械に任せられるのは3と4、条件つきで2だ。1の執筆は当然として、5の入稿もKDPの管理画面での操作が必要になるため人の手が残る。逆にいえば、**組版と検査を自動化するだけで、繰り返し発生する作業のほとんどが消える**。

## 原稿と体裁を分ける

工程を分けるうえで決定的なのは、原稿と体裁を別々のファイルに置くことだ。Wordで直接書くと、この2つが混ざる。段落の見た目を整えた瞬間、その原稿は「その体裁でしか使えないもの」になる。

Markdownで書けば、原稿には構造だけが残る。

```markdown
# 第1章　制作工程を分解する

## 5つの工程

個人出版の制作工程は、おおよそ次の5つに分けられる。
```

`#`は章、`##`は節。それが何ポイントの何というフォントで組まれるかは、原稿には書かない。体裁は`book.yaml`が持つ。

> 原稿は構造を、設定は体裁を持つ。この分離ができていれば、判型を変えたくなったときに触るのは設定ファイル1行だけで済む。

## 出力は1つではない

もうひとつ意識しておきたいのは、同じ原稿から複数の成果物が要るということだ。電子書籍とペーパーバックでは、必要な体裁が違う。

- 電子書籍: 判型を持たない。読者が文字サイズを変える。目次はリンクで飛ぶ
- ペーパーバック: 判型が固定。ノド側の余白を広く取る。目次にページ番号が要る

この2つを手作業で作り分けると、原稿を直すたびに二重の手間がかかる。ビルドスクリプトに**プロファイル**という考え方を持ち込んで、同じ原稿から両方を吐かせるのが本書の方針だ。
