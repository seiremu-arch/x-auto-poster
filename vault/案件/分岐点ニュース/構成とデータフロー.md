# 構成とデータフロー

[[分岐点ニュース]] が記事を取得してから公開されるまでの流れ。

## 流れ

1. `.github/workflows/daily-update.yml` が cron `0 21 * * *`(= 06:00 JST)で起動する → [[GitHub Actions]]
2. Python 3.11 をセットアップし、`pip install -r requirements.txt`(`feedparser==6.0.11` のみ)
3. `scripts/generate_site.py` が `config/feeds.json` を読む
4. フィードごとに最大8件(`MAX_ARTICLES_PER_FEED`)取得 → [[RSSフィード収集]]
5. フィードの `category`(`fact` / `opinion`)でバケツに振り分ける → [[事実と意見の分類]]
6. カテゴリごとに公開日時の降順で並べ、上位20件(`MAX_ARTICLES_PER_CATEGORY`)に絞る
7. HTMLを文字列として組み立てて `docs/index.html` に書き出す → [[静的HTML生成スクリプト]]
8. 差分があれば `github-actions[bot]` 名義でコミット・プッシュ
9. GitHub Pages が `main` の `/docs` を配信する → [[GitHub Pages]]

## ファイルの役割

| パス | 役割 |
| --- | --- |
| `config/feeds.json` | フィード定義(`name` / `url` / `category`) |
| `scripts/generate_site.py` | 取得・分類・HTML生成の全部 |
| `docs/index.html` | 生成物。手で編集しない(次回実行で上書きされる) |
| `.github/workflows/daily-update.yml` | 定期実行と自動コミット |
| `requirements.txt` | `feedparser==6.0.11` |

## 設計上のポイント

- **1フィードの失敗で全体を止めない**: `fetch_feed_articles()` が例外を握りつぶしてエラー文字列を返し、ページ下部の「取得できなかったフィード」に出す。→ [[フィード運用メモ]]
- **公開日時が取れない記事**: `published_parsed` も `updated_parsed` も無い場合は `None` になり、ソート時は最古扱い(`datetime.min`)。時刻表示も省略される。
- **テンプレートエンジンを使わない**: f-string でHTMLを組み立て、CSSの `{` は `{{` にエスケープしている。依存を `feedparser` だけに保つための割り切り。
- **エスケープ**: タイトル・リンク・ソース名は `html.escape()` を通す。ただし記事の `summary` は取得しているが現状レンダリングしていない。
