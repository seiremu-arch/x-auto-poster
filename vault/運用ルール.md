# 運用ルール

このvault([[ホーム]])の書き方の取り決め。新しく案件やナレッジが出てきたら、既存ノートに追記するのではなく **新しいフォルダ/ファイルを作り、リンクで繋ぐ**。

## フォルダ構成

```
vault/
├── ホーム.md            入口(MOC)
├── 運用ルール.md         このファイル
├── 案件/                案件ごとに1フォルダ
│   └── <案件名>/
│       ├── <案件名>.md   案件ハブノート(フォルダ名と同名)
│       └── ...           その案件専用のノート
├── ナレッジ/             再利用する知識。分野ごとに1フォルダ
│   └── <分野>/
│       └── <トピック>.md
└── テンプレート/
```

- 案件フォルダの直下に、フォルダ名と同名のハブノートを必ず1枚置く。案件の入口はそこだけ。
- 案件専用の詳細(設計・運用メモなど)は、ハブノートに書き足すのではなく別ファイルに切り出してリンクする。
- 他の案件でも使える知識になった時点で `ナレッジ/` に切り出し、案件ノートからはリンクだけ張る。

## リンクの張り方

- リンクは `[[ノート名]]` のウィキリンクを使う。パスは書かない(Obsidianの設定で最短表記にしてある)。
- 表示名を変えたいときは `[[ノート名|表示名]]`。
- 新しいノートを作ったら、**必ず** 次の2方向を繋ぐ:
  1. 上位のノート(案件ハブ、または [[ホーム]])から新ノートへのリンク
  2. 新ノートから関連ノートへのリンク(最低1本)
- リンク先が未作成のまま `[[...]]` を書くのは可。Obsidian上では未作成リンクとして表示され、後から埋める目印になる。

## ファイル名

- 日本語のまま、内容がわかる名前を付ける。連番や日付のプレフィックスは付けない。
- `/ \ : | # ^ [ ]` はファイル名に使わない(Obsidianのリンクが壊れる)。

## フロントマター

全ノートの先頭に付ける。

```yaml
---
type: 案件 | ナレッジ | 運用 | テンプレート | ホーム
status: 進行中 | 保留 | 完了     # 案件のみ
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags:
  - 案件/<案件名>                # その案件に属するノート
  - <分野>                       # ナレッジの分野
---
```

- `updated` は内容を実質的に変えたときだけ更新する。
- タグは階層タグ(`案件/分岐点ニュース`)を使い、案件横断の検索に使う。

## ノートの作り方

手で作ってもいいが、雛形と [[ホーム]] へのリンク追加をまとめてやるスクリプトがある。

```bash
python scripts/new_note.py 案件 "新しい案件名"
python scripts/new_note.py ナレッジ "トピック名" --分野 GitHub
```

詳細は [[ノート作成スクリプト]] を参照。
